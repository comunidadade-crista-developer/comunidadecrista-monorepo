# ADR-007 — Offline-first com outbox local + idempotency keys

**Estado**: Aceite

**Contexto**: rede intermitente e servidor que dorme.
**Decisão**: cliente gera UUID v7 e `idempotency_key` por operação; server deduplica em `idempotency_keys`; retry exponencial no cliente e no servidor.
**Consequências**: contrato `/sync` é crítico — precisa de testes E2E rigorosos.

**Estado (E4-b/E4-c)**: o contrato está em `packages/shared/src/sync.ts` e `docs/api/api.md`. Cada operação é aplicada pelo mesmo serviço que o REST, numa transacção própria; só `post.create` usa `idempotency_key` (reservada antes de criar, com _hash_ do pedido: mesma chave com outro corpo → `idempotency_key_conflict`); as restantes operações são idempotentes por natureza e devolvem `duplicate` quando já estavam aplicadas. O `/sync` paga os mesmos limites por operação que o REST e tem prazo (`SYNC_BATCH_TIMEOUT_MS`).
