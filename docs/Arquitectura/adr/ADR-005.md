# ADR-005 — Outbox table em Postgres + worker in-process

**Estado**: Aceite

**Contexto**: Render free só oferece um web service gratuito; background workers são pagos.
**Decisão**: tabela `outbox` no Postgres, worker a correr dentro do processo Fastify via `setInterval`, com `SELECT ... FOR UPDATE SKIP LOCKED`.
**Consequências**: o worker dorme quando o serviço dorme — eventos internos (notificar admin, purgas, caches) processam-se no próximo wake. Aceitável para o domínio.

**Estado (E4-c)**: implementado em `workers/outbox-worker.ts` (`OUTBOX_WORKER_INTERVAL_MS`, `OUTBOX_WORKER_BATCH_SIZE`; desligado nos testes). Ainda não existem consumidores: um evento sem _handler_ é dado como concluído, para a tabela não crescer sem limite (cada like gera um evento); a purga de `done` corre no job de manutenção (7 dias). Um _handler_ que lança devolve o evento à fila com atraso exponencial (1 s … 5 min) e passa a `failed` à 6.ª tentativa. Seguro com várias instâncias (`FOR UPDATE SKIP LOCKED` + janela de visibilidade).
