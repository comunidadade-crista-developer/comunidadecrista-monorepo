# ADR-013 — Filtro anti-spam no conteúdo

**Data**: 2026-11-02
**Estado**: Aceite
**Contexto**: E4 fechado (posts, likes, denúncias). Antes de E5 (sync) e E6 (admin), decidimos blindar a pré-publicação contra engenharia social mecânica.

## Decisão

Aplicar um filtro no `createPostService` que **rejeita** conteúdo com links/contactos e **sinaliza para revisão** conteúdo com sinais de spam. **Não** aplicar filtro doutrinal — a doutrina é defendida por denúncias + admin.

## Alternativas consideradas

1. **Filtro semântico (NLP)** — rejeitado: custo, latência, falso positivo em conteúdo legítimo, requer modelo.
2. **Blocklist doutrinal** — rejeitado: falsos positivos em vocabulário legítimo ("depressão", "sexo no casamento"), opaco ao utilizador, mantém "lista secreta".
3. **Só denúncias** — insuficiente: spam mecânico chega ao feed antes de ser reportado.
4. **Pendente automático para toda conta nova** — rejeitado pelo stakeholder: "se for a crescer vai ser difícil validar todos posts". Escala mal.

**Escolhida**: filtro de sinais mecânicos (links, contactos, spam patterns) + denúncias por severidade.

## Regras (final)

### Normalização (antes de qualquer detecção)
```
NFKC → remover zero-width → remover combining decorativo → colapsar whitespace → lowercase
```

### A) Rejeição imediata (`400`)

| Tipo | Padrão |
|---|---|
| Scheme | `\b(https?\|hxxps?\|ftp\|ftps)\s*:\s*/{1,2}` |
| `www.` | `\bwww\s*\.` |
| TLD | `\.(com\|xyz\|top\|buzz\|bond\|sbs\|cfd\|li\|ru\|es\|dev\|icu\|tk\|ml\|ga\|cf\|gq\|zip\|mov)\b` |
| Multi-parte | `\.(pages\.dev\|vercel\.app\|github\.io\|netlify\.app\|workers\.dev\|dweb\.link\|co\.uk\|com\.br)\b` |
| IPv4 | `\b\d{1,3}(\.\d{1,3}){3}\b` |
| IPv6 curto | `\b([a-f0-9]{1,4}:){2,}[a-f0-9]{1,4}\b` |
| Email | `[a-z0-9._%+-]+\s*(@\|＠\|\(at\)\|\[at\])\s*[a-z0-9.-]+\.[a-z]{2,}` |
| Telefone PT | `\b(\+351\|00351)?[\s-]?9[1236]\d{7}\b` |

**Nota `.com`**: `\b` no fim evita falsos positivos em "comunidade", "comum". Só casa `.com` em boundary.

**Nota bíblica**: `"João 3:16"` não é telefone (9 dígitos PT começam por `9[1236]`). `"Mateus 2:1-12"` não é IP.

### B) Sinais de spam (não rejeita — sinaliza `pending_review`)

| Sinal | Regra |
|---|---|
| ALL CAPS | `len > 50 && > 50% letras maiúsculas` |
| Repetição | `/(.)\1{9,}/` |
| Pontuação | `/[!?]{5,}/` |
| Keywords | `bitcoin, criptomoeda, investimento garantido, ganhe dinheiro, ganhos rápidos, clique aqui, prémio, sorteio, renda extra, multiplica teu dinheiro` |

**Hardcoded** — sem env. Ajustável por PR (auditável em git, não em runtime).

### C) Não há auto-pending por conta

**Rejeitado**. Conta nova publica directamente se conteúdo passar A e B. Defesa em profundidade fica por conta de:
- Rate limit 10/h em `posts.create`
- Filtro A/B
- Denúncias rápidas (severidade)
- Admin (E6)

Se surgir evidência de abuso organizado por contas novas, revisitamos. Não é problema pré-resolvido.

## Fluxo (`createPostService`)

```
1. Normalizar título + conteúdo
2. Se containsLink(título ∪ conteúdo)    → rejeita 400 contains_link
3. Se containsContact(título ∪ conteúdo) → rejeita 400 contains_contact
4. Se spamSignals(título ∪ conteúdo)     → status = 'pending_review'
   Senão                                 → status = 'published'
5. Persiste post + outbox
```

## Consequências

**Positivas**
- Zero falsos positivos de doutrina (não filtra doutrina)
- Testável, determinístico
- Explicável ao utilizador ("não aceitamos links")
- Alinhado com open source (regras no repo, não em DB secreta)

**Negativas**
- Utilizador legítimo com `.com` da igreja é rejeitado → fricção; mitigada por mensagem clara
- Contas novas spam (sem sinais B) passam → admin apanha pós-report
- `ALL CAPS` legítimo cai em review → custo de admin

**Neutras**
- `/sync` herda automaticamente (mesmo serviço)
- Interface em `packages/shared/src/content-filter.ts` — cliente e servidor partilham regras

## Interface pública

```ts
// packages/shared/src/content-filter.ts
export interface ContentViolation {
  kind: 'link' | 'contact' | 'spam_signal';
  hint: string;
}

export type ContentCheckResult =
  | { reject: false; flags: ContentViolation[] }
  | { reject: true; violations: ContentViolation[] };

export function checkContent(title: string, content: string): ContentCheckResult;
```
