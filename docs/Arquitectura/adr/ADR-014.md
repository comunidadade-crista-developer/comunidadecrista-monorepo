# ADR-014 — Severidade de denúncias

**Data**: 2026-11-02
**Estado**: Aceite
**Contexto**: Regra actual — 10 denúncias → `pending_review` — trata spam e "ensino contrário à Palavra" da mesma forma. Falso negativo: doutrina exige mais urgência que spam.

## Decisão

Categorizar denúncias em três níveis de severidade, com thresholds distintos. Continuar a usar `pending_review` como único escalonamento (sem auto-hide permanente, sem auto-delete).

## Mapeamento

| Label PT-PT (UI) | Código | Severidade | Threshold |
|---|---|---|---|
| Spam ou publicidade | `spam` | `basic` | 10 |
| Fora do tema | `off_topic` | `basic` | 10 |
| Ofensa ou desrespeito | `offensive` | `medium` | 5 |
| Ensino contrário à Palavra | `doctrine` | `high` | 2 |
| Outro motivo | `other` | `basic` | 10 |

**Regra `reason`**: opcional em todas, **obrigatório em `other`**.

## Lógica de escalonamento

Contando **apenas denúncias válidas** (reportante ≥ 7 dias E ≥ 1 post, regra existente):

```
count(spam)     + count(off_topic) + count(other)  ≥ 10  → pending_review
count(offensive)                                    ≥  5  → pending_review
count(doctrine)                                     ≥  2  → pending_review
```

Escala se **qualquer** condição for verdadeira. Não há somas cruzadas (4 basic + 4 medium + 1 high = não escala).

## Riscos aceites

- 2 users maliciosos silenciam via `doctrine` → mitigação: 1 denúncia/user/post, validação de conta, admin revê, log de abuso
- Cancelamento após escalonamento **não reverte** `pending_review` (consistente com comportamento actual)
- Sem reputação de repórter no MVP → decisão pós-MVP se houver abuso

## Schema (migração)

```sql
CREATE TYPE report_category AS ENUM ('spam', 'off_topic', 'offensive', 'doctrine', 'other');
CREATE TYPE report_severity AS ENUM ('basic', 'medium', 'high');

ALTER TABLE reports
  ADD COLUMN category report_category NOT NULL DEFAULT 'other',
  ADD COLUMN severity report_severity NOT NULL DEFAULT 'basic';

CREATE INDEX reports_post_category_status_idx ON reports (post_id, category, status);
```

**Migração de dados**: denúncias existentes ficam `other`/`basic` (threshold 10, idêntico ao actual). Zero regressão.

`severity` é derivada de `category` no insert (hardcoded no repo) e guardada para query rápida. Mapping pode mudar sem reescrever reports (UPDATE em migration futura).

## API breaking changes

### `POST /posts/:id/report`

**Antes**: `{ reason: string }`
**Depois**:
```ts
{ category: ReportCategory, reason?: string }  // reason obrigatório se category='other'
```

### `SyncReportPost` (E5)

Payload idêntico ao REST.

### Schema (`packages/shared/src/posts.ts`)

```ts
export const ReportCategory = z.enum(['spam', 'off_topic', 'offensive', 'doctrine', 'other']);

export const ReportRequest = z.object({
  category: ReportCategory,
  reason: z.string().min(3).max(500).optional(),
}).refine(
  (d) => d.category !== 'other' || (d.reason && d.reason.length >= 3),
  { message: 'motivo obrigatório', path: ['reason'] },
);
```

## Lógica no `reportsRepo.file`

```ts
file(args: { postId, reporterId, category, reason? }, rules?): Promise<FileReportOutcome>
```

`rules.thresholds` opcional, defaults `{ basic: 10, medium: 5, high: 2 }`.

Cálculo por query na transacção (não desnormalizar por severidade — volume é baixo).

## Admin (E6)

Dashboard mostra por post: `3 spam, 2 ofensivo, 1 doutrina`. Permite decisão informada.
